This tutorial connects `ghostty-webgpu` to a live Bash session using Bun's built-in PTY API on Linux or macOS. It requires Bun 1.4.2 or newer, `bash` on your `PATH`, and the browser client from [Connect to a PTY](https://ghostty.shaulavo.dev/docs/guides/pty/).

## 1. Start the local PTY server

Save this file as `pty-server.ts`. Each incoming WebSocket spawns an isolated `bash --noprofile --norc` child attached to a PTY.

<Code code={sample} lang='ts' title='pty-server.ts' />

Start the server:

```sh
bun pty-server.ts
```

It prints `Shell WebSocket listening at ws://127.0.0.1:8080/pty`.

## 2. Connect the browser client

In your browser entry point, use `connectShell(host, 'ws://127.0.0.1:8080/pty')` from [Connect to a PTY](https://ghostty.shaulavo.dev/docs/guides/pty/).

The wire protocol separates data and control cleanly:

- **Binary frames** carry raw terminal bytes in both directions (browser `onData` bytes to the PTY, PTY stdout to `terminal.write`).
- **Text frames** carry JSON resize messages (`{ type: 'resize', columns, rows }`). Because `await terminal.open(host)` fits the grid before resolving, the initial `open` handler sends the true container size immediately.

## 3. Verify output and resize sync

Type `printf 'Hello from Bash\n'` and press Enter to confirm round-trip byte delivery. Then resize the browser window and run `stty size`. The reported rows and columns should match `terminal.geometry()`.

## Troubleshooting

### Bun throws when spawning the terminal

Bun's `terminal` option in `Bun.spawn` requires Linux or macOS and Bun 1.4.2+. Confirm `which bash` succeeds in the same shell where you launch `bun pty-server.ts`.

### The browser blocks `ws://`

Pages served over `https://` cannot open insecure `ws://` sockets. Run this tutorial from a local `http://localhost` or `http://127.0.0.1` dev server, and terminate TLS (`wss://`) in front of any deployed PTY endpoint.

## Security before deploying

This local server spawns a shell with your OS user's permissions and binds only to `127.0.0.1`. It rejects non-loopback `Origin` headers, validates integer grid bounds (`1..500` columns, `1..200` rows), and closes sockets that send malformed JSON. Before exposing a PTY endpoint on a network, add authentication, an explicit `Origin` allowlist, per-user container or OS isolation, connection rate limits, and bounded output queues.

Continue with [Connect to a PTY](https://ghostty.shaulavo.dev/docs/guides/pty/) for backpressure, reconnection, and worker output ports.
