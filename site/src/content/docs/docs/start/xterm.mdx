`ghostty-webgpu` exposes its own native API rather than an xterm.js compatibility layer. Most of the migration is mechanical once you adjust to four core design differences.

## Four mental-model shifts

1. **Creation and opening are async.** `await Terminal.create(opts)` loads WebAssembly and builds the native session; `await terminal.open(host)` measures the container, fits the initial grid, and starts the renderer.
2. **I/O stays in raw bytes.** `onData` delivers `{ bytes: Uint8Array, origin }` instead of UTF-16 strings. Pass incoming PTY `Uint8Array` chunks straight to `terminal.write(bytes)`.
3. **Fitting and GPU rendering are built in.** You no longer install separate fit, WebGL, Unicode, or web-links addons. `open()` fits synchronously and `ResizeObserver` tracks future container or DPR changes automatically.
4. **Colors are RGB objects, not CSS strings.** `TerminalTheme` takes `{ r, g, b }` integers and a 256-entry `palette` array, with `minimumContrast` built right into the theme.

For programmatic input, use `sendInput()` for raw bytes or text, `paste()` for bracketed paste, and `key()` for synthesized keystrokes. Subscribe to `title`, `bell`, `selection`, `scroll`, `appearance`, `error`, and `outputTiming` via `terminal.on(type, listener)`.

## Addon replacements

| xterm.js addon                      | ghostty-webgpu equivalent                                                                        | Status       |
| ----------------------------------- | ------------------------------------------------------------------------------------------------ | ------------ |
| `@xterm/addon-fit`                  | Built-in `ResizeObserver` fitter; `await term.open(host)` fits synchronously                     | Built in     |
| `@xterm/addon-webgl`                | `rendererMode: 'auto'` selects WebGPU or WebGL2 with Canvas-first startup and automatic fallback | Built in     |
| `@xterm/addon-unicode11` / grapheme | Native `libghostty-vt` widths and DEC mode 2027 grapheme clustering                              | Built in     |
| `@xterm/addon-web-links`            | Built-in URL detection, OSC 8 hyperlinks, and `registerLinkProvider` (main and worker)           | Built in     |
| `@xterm/addon-clipboard`            | Host `clipboardWrite` policy for OSC 52 writes (denied by default); OSC 52 reads get no reply    | Write policy |
| `@xterm/addon-attach`               | Binary WebSocket recipe in [Wire a PTY](https://ghostty.shaulavo.dev/docs/guides/pty/)           | Guide        |
| `@xterm/addon-ligatures`            | `ligatures` option reading the font's `GSUB` table                                               | Opt in       |
| `@xterm/addon-serialize`            | `readLines()`, `getSelection()` (`plain`, `vt`, `html`), and `captureViewport()`                 | Partial      |
| `@xterm/addon-search`               | Retained-buffer search                                                                           | Planned      |
| `@xterm/addon-image`                | Sixel and Kitty graphics protocols                                                               | Planned      |

`registerMarker`, `registerDecoration`, and custom xterm parser hooks do not have public equivalents; custom OSC observation is available on `TerminalSession`. See [status and limits](https://github.com/ShaulLavo/ghostty-webgpu/blob/main/docs/status.md) for current scope.

<Aside type="caution" title="Pitfall: scrollback and font timing">

Two subtle differences catch xterm.js users during migration:

- **Scrollback is page-granular.** Ghostty prunes whole memory pages rather than individual lines. Configure `appearance.scrollbackLimit` and `appearance.scrollbackByteLimit`, and always check `lineCount()` for the exact retained row count.
- **Preload web fonts before `open()`.** Await `document.fonts.load(...)` first so the synchronous initial fit measures your real font instead of a fallback monospace face.

</Aside>

## Performance and bundle tradeoffs

Compare matching renderer classes in [Benchmarks](https://ghostty.shaulavo.dev/docs/concepts/benchmarks/). `ghostty-webgpu` uses significantly less CPU under heavy streaming and multi-terminal workloads (median `0.71x` on Linux PC, `0.77x` on M1 Mac across the November 2026 five-way suite), while xterm.js ships a smaller initial download (`84.1 KiB` brotli vs. `269.2 KiB` brotli).
