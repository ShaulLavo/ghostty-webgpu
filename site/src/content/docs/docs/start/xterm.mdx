title: Coming from xterm.js
description: Map xterm.js constructors, events, and addons to ghostty-webgpu's native API.

`ghostty-webgpu` is not an xterm.js drop-in shim. Construction and opening are asynchronous, input events carry raw `Uint8Array` bytes, fitting happens automatically during `open()`, and main-thread writes update native state synchronously. Start with [First terminal](https://ghostty.shaulavo.dev/docs/start/quick-start/), then port your transport and options using the tables below.

For programmatic input, use `sendInput` for raw text or bytes, `paste` for bracketed paste, and `key` for synthesized key events. Subscribe to `title`, `bell`, `selection`, `scroll`, `appearance`, `error`, and `outputTiming` via `terminal.on(type, listener)`.

## Addon replacements

| xterm.js addon                      | ghostty-webgpu equivalent                                                                         | Status       |
| ----------------------------------- | ------------------------------------------------------------------------------------------------- | ------------ |
| `@xterm/addon-fit`                  | Built-in `ResizeObserver` fitter; `await term.open(host)` fits before resolving                   | Built in     |
| `@xterm/addon-webgl`                | `rendererMode: 'auto'` selects WebGPU or WebGL2 with Canvas-first startup and automatic fallback  | Built in     |
| `@xterm/addon-unicode11` / grapheme | Native `libghostty-vt` widths and DEC mode 2027 grapheme clustering                               | Built in     |
| `@xterm/addon-web-links`            | Built-in URL detection, OSC 8 hyperlinks, and `registerLinkProvider` (main and worker)            | Built in     |
| `@xterm/addon-clipboard`            | Host `clipboardWrite` policy for OSC 52 writes (denied by default); OSC 52 reads receive no reply | Write policy |
| `@xterm/addon-attach`               | Binary WebSocket recipe in [Connect to a PTY](https://ghostty.shaulavo.dev/docs/guides/pty/)      | Guide        |
| `@xterm/addon-ligatures`            | `ligatures` option reading the font's `GSUB` table                                                | Opt in       |
| `@xterm/addon-serialize`            | `readLines()`, `getSelection()` (`plain`, `vt`, `html`), and `captureViewport()`                  | Partial      |
| `@xterm/addon-search`               | Retained-buffer search                                                                            | Planned      |
| `@xterm/addon-image`                | Sixel and Kitty graphics protocols                                                                | Planned      |

`registerMarker`, `registerDecoration`, and custom xterm parser hooks do not have public equivalents. Custom OSC observation is available on `TerminalSession`. See [status and limits](https://github.com/ShaulLavo/ghostty-webgpu/blob/main/docs/status.md) for current capability boundaries.

## Appearance and scrollback differences

- **Colors are RGB objects, not CSS strings.** `TerminalTheme` takes `{ r, g, b }` entries and a 256-entry `palette`. `minimumContrast` lives on the theme.
- **Scrollback is page-granular.** Set `appearance.scrollbackLimit` (physical history rows) and `appearance.scrollbackByteLimit` (page memory budget). Ghostty prunes whole pages, so read `lineCount()` for the exact retained row count.
- **Fonts should load before `open()`.** Await `document.fonts.load(...)` first so the synchronous initial fit measures the real font metrics instead of a fallback monospace face.

See [Benchmarks](https://ghostty.shaulavo.dev/docs/concepts/benchmarks/) for the November 2026 five-way comparison and paired Mac M1 ratios against xterm.js 6.0.0.
