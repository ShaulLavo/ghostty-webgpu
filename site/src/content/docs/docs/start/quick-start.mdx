## Install the package

Install `ghostty-webgpu` with your package manager. Any bundler that serves `.wasm` assets (Vite, esbuild, Webpack, Bun) works out of the box.

```sh
npm install ghostty-webgpu
```

<Aside type='note' title='WASM asset serving'>
  Make sure your bundler emits `ghostty-vt.wasm`, `bridge.wasm`, `canvas-compose.wasm`, and
  `canvas-compose-scalar.wasm` with `Content-Type: application/wasm`. For custom asset paths or
  linking from a local checkout, pass explicit URLs via `runtime` and `compositorAsset` (see [Use
  ghostty-webgpu in your own
  app](https://github.com/ShaulLavo/ghostty-webgpu/blob/main/docs/use-in-your-app.md)).
</Aside>

## Give the host container a size

Place a container element with a concrete height in your page:

```html title="index.html"
<div id="terminal" style="height: 20rem; width: 100%"></div>
```

<Aside type='caution' title='Pitfall: zero-height containers'>
  `await terminal.open(host)` measures `host` synchronously and sizes the initial grid before
  painting the first frame. If `host` has `0px` height when `open()` runs (common inside an
  unconstrained flex item missing `min-height: 0`), the terminal keeps the default `80x24` grid
  until `ResizeObserver` sees a nonzero size. Give the container an explicit height up front so
  frame one lands at the true dimensions.
</Aside>

## Mount your first terminal

Creation and opening are both asynchronous because `Terminal.create()` loads and compiles the WebAssembly modules, and `open(host)` mounts the DOM host and initializes the renderer.

<Code code={minimal} lang='ts' title='terminal.ts' />

Here is what happens at each step:

1. **`await Terminal.create()`** loads `ghostty-vt.wasm` and `bridge.wasm` and constructs an owned `libghostty-vt` session.
2. **`await terminal.open(host)`** measures `host`, computes the integer device-pixel cell grid, mounts the canvas, and starts Canvas-first rendering while WebGPU or WebGL2 warms up in the background.
3. **`terminal.writeln(...)`** feeds UTF-8 bytes directly into `libghostty-vt`. On the main entry, native writes update emulator state synchronously and schedule a paint on the next animation frame.
4. **`terminal.onData(({ bytes }) => ...)`** fires whenever keyboard or paste input produces VT bytes. In a real app you forward `bytes` straight to a PTY socket; in this minimal example we loop them back into `terminal.write(bytes)`.
5. **`terminal.dispose()`** tears down observers, event listeners, GPU resources, and WASM memory. Always call the disposer when your view or component unmounts.

<details class='deep-dive'>
  <summary>Why open() paints at full size with no flash</summary>
  <div class='deep-dive__body'>
    <p>
      Before constructing the renderer, <code>TerminalHost.open()</code> measures the container's
      content box, font metrics, padding, and scrollbar reservation, then resizes the native{' '}
      <code>libghostty-vt</code> grid and styles the canvas to those exact pixel dimensions.
    </p>
    <p>
      In default <code>frame</code> presentation mode, <code>CanvasTerminalRenderer</code> paints
      the first frame immediately while WebGPU or WebGL2 compiles its shaders on a separate
      offscreen canvas. Once the GPU canvas paints a matching frame, the host swaps it in place with
      zero layout shift.
    </p>
  </div>
</details>

## Add local line editing and Ghostty shortcuts

A bare terminal only displays bytes and emits encoded keystrokes; normally a shell like Bash or Zsh handles prompts, Backspace, arrow keys, and command history. When you are building a local prompt with no remote shell, add `@ghostty-webgpu/line-editor` and `@shaulavo/hotkeys`:

```sh
npm install @ghostty-webgpu/line-editor @shaulavo/hotkeys
```

<Code code={echoSample} lang='ts' title='echo.ts' />

- `attachTerminalHotkeys(terminal)` binds Ghostty's keyboard shortcuts (`Cmd+C`, `Cmd+K`, font zoom, page scroll) before `open()`.
- `terminal.use(readline())` installs the line-editor extension so `editor.read({ prompt: '$ ' })` handles editing, history, and Ctrl+C locally.
- `accessibility: {}` turns on the opt-in screen-reader text mirror.
- Calling `terminal.dispose()` rejects the pending `editor.read()` promise cleanly, ending the loop.

<Aside type='tip' title='Moving to a real shell'>
  When you connect a real PTY in [Connect a real
  shell](https://ghostty.shaulavo.dev/docs/start/real-shell/), drop `@ghostty-webgpu/line-editor`.
  The remote shell owns line editing, and your browser code simply forwards `onData` bytes to the
  WebSocket.
</Aside>
