---
title: Coming from ghostty-web
description: Move from ghostty-web's xterm-style wrapper to ghostty-webgpu's native API and GPU renderers.
---

Both libraries compile Ghostty's `libghostty-vt` to WebAssembly, but `ghostty-webgpu` uses its own native API rather than an xterm.js compatibility wrapper and adds Zig frame building, WebGPU/WebGL2/Canvas/DOM renderers, and worker execution.

## Key differences

| ghostty-web 0.4.0                              | ghostty-webgpu                                                                                        |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Separate `init()` followed by `new Terminal()` | `await Terminal.create(options)`, then `await terminal.open(host)`                                    |
| String callbacks in `onData`                   | `onData(({ bytes, origin }) => ...)` delivers raw `Uint8Array` bytes                                  |
| Single Canvas 2D renderer                      | Canvas-first startup handing off to WebGPU or WebGL2, with Canvas 2D and DOM fallbacks                |
| External fit addon                             | Automatic synchronous fit during `open()` plus `ResizeObserver` tracking                              |
| Flat font and theme options                    | Structured `appearance.font`, `appearance.theme` (RGB objects + 256-entry palette), `setAppearance()` |
| Main-thread execution only                     | Main entry (`ghostty-webgpu`) and worker entry (`ghostty-webgpu/worker`) with `TerminalWorkerPool`    |

Check [Coming from xterm.js](https://ghostty.shaulavo.dev/docs/start/xterm/) for a full method-by-method table.

## Keep I/O as bytes

Avoid decoding terminal output to JavaScript strings on the hot path. Set `socket.binaryType = 'arraybuffer'`, pass `new Uint8Array(event.data)` to `terminal.write()`, and send `event.bytes` from `terminal.onData` directly back to the PTY. `libghostty-vt` handles UTF-8 sequences split across chunks natively. See [Connect to a PTY](https://ghostty.shaulavo.dev/docs/guides/pty/) for the complete client.

## Load fonts before opening

For the main entry, load faces into `document.fonts` before calling `open()` ([Load fonts and fit the grid](https://ghostty.shaulavo.dev/docs/guides/fonts/)). For `ghostty-webgpu/worker`, pass font URLs or raw `Uint8Array` bytes in the `fonts` option because workers do not share the page's `document.fonts` set.

## Tradeoffs to check

- **Bundle size and cold load:** `ghostty-web` 0.4.0 downloads 146.1 KiB brotli (41 ms PC / 61 ms Mac unthrottled cold paint). `ghostty-webgpu` downloads 269.2 KiB brotli (80 ms PC / 101 ms Mac) because it ships the unpatched upstream `libghostty-vt` build, `bridge.wasm`, and the Canvas compositor alongside the GPU renderers.
- **CPU under load and correctness:** In the November 2026 benchmarks, `ghostty-webgpu` uses a fraction of `ghostty-web`'s CPU on dense output and 16-terminal workloads and survives the unpaced 1 MiB write-queue overload and Unicode burst cases where `ghostty-web` 0.4.0 crashes. See [Benchmarks](https://ghostty.shaulavo.dev/docs/concepts/benchmarks/) and [correctness](https://github.com/ShaulLavo/ghostty-webgpu/blob/main/docs/correctness.md).
- **Features:** DEC mode 2026 synchronized output, mode 2027 grapheme clustering, opt-in GSUB ligatures, lazy BiDi, OSC 8 links, and host-side link providers are shipped. Retained-buffer search and Sixel/Kitty images are not built yet.
