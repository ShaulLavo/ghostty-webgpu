`ghostty-webgpu` derives a single integer device-pixel cell grid from your font metrics and uses it across layout, pointer projection, selection, and every renderer so columns never drift across high-DPI or fractional pixel ratios.

## 1. Load web fonts before calling `open()`

<Code code={sample} lang='ts' title='fonts.ts' />

Wait for your `FontFace` (or `document.fonts.load(...)` for CSS `@font-face` rules) before `Terminal.create()` and `open()`. When the face is already loaded, `open()` fits the container synchronously on the very first frame with no fallback-font flash. If a font finishes loading later, the built-in `document.fonts` observer re-measures the grid and clears the glyph atlas automatically.

For worker terminals, supply faces through the `fonts` creation option instead of `document.fonts`. See [Run in a worker](https://ghostty.shaulavo.dev/docs/guides/workers/).

## 2. Font geometry and live updates

Call `terminal.setFont(partial)` to change `family`, `size`, `lineHeight`, `letterSpacing`, `weight`, or `boldWeight` at runtime.

- `size` is the CSS em size in pixels. Measured row height includes ascent and descent, so a 14 px font at `lineHeight: 1.2` produces a taller cell than 14 px.
- `lineHeight` multiplies the natural font box and must be at least `0.5`. Values below `1` center glyphs inside a shorter cell and clip them to their cell span.
- `letterSpacing` adjusts horizontal advance in CSS pixels; negative values are allowed as long as the fitted device cell width stays positive.
- Every cell width and height rounds to whole device pixels (`cssCellWidth * pixelRatio` is an exact integer) so adjacent rows and box-drawing glyphs align without subpixel seams. See the [font geometry specification](https://github.com/ShaulLavo/ghostty-webgpu/blob/main/docs/font-geometry.md) for the exact formulas.

## 3. Unicode widths, emoji, and ligatures

- **Cell widths:** `libghostty-vt` decides whether a code point occupies 1 or 2 cells; browser font fallback only draws the pixels inside that span. When an application enables DEC mode 2027 (grapheme clustering), ZWJ sequences such as `👩‍💻` occupy 2 cells and stay intact across byte-by-byte writes.
- **Ligatures:** Off by default. Enable programming ligatures by passing `ligatures` in `Terminal.create()`. The renderer reads the font's `GSUB` table to split and shape joined runs without changing underlying cell ownership.
- **BiDi:** Off by default. Pass `bidi: true` to lazy-load Unicode 13.0 bidirectional row reordering (`bidi-js`) for right-to-left scripts.

## Troubleshooting

### The terminal briefly renders in the wrong font

Wait for `document.fonts.load('400 14px "Your Font"')` before `open()`, match the exact family string in `appearance.font.family`, and verify the font response includes CORS headers when served from another origin.

### Rows look taller than expected

Inspect `terminal.appearance.grid.cellHeight` and check both `lineHeight` and the font's intrinsic ascent/descent metrics.
