The core `Terminal` encodes VT keys and Kitty keyboard protocol sequences without forcing an opinionated shortcut table. To add Ghostty's keymap, install the optional `@shaulavo/hotkeys` peer dependency and import `attachTerminalHotkeys` from `ghostty-webgpu/hotkeys`.

## 1. Attach before opening

<Code code={sample} lang='ts' title='hotkeys.ts' />

Call `attachTerminalHotkeys(terminal, options)` before `terminal.open(host)`. The connection claims original keyboard input via `terminal.connectInput()` once the terminal opens, and disposing either the connection or the terminal tears down listeners and aborts pending clipboard work. Only one original-input owner can be connected to a terminal at a time.

## 2. Default Ghostty keymap

| Action                  | macOS                        | Linux and Windows                |
| ----------------------- | ---------------------------- | -------------------------------- |
| Copy selection          | `Cmd+C`                      | `Ctrl+Shift+C`                   |
| Select all              | `Cmd+A`                      | `Ctrl+Shift+A`                   |
| Clear above prompt      | `Cmd+K`                      | `Ctrl+Shift+K`                   |
| Increase font size      | `Cmd+=`                      | `Ctrl+=`                         |
| Decrease font size      | `Cmd+-`                      | `Ctrl+-`                         |
| Reset font size         | `Cmd+0`                      | `Ctrl+0`                         |
| Scroll to top or bottom | `Cmd+Home`, `Cmd+End`        | `Shift+Home`, `Shift+End`        |
| Scroll one page         | `Cmd+PageUp`, `Cmd+PageDown` | `Shift+PageUp`, `Shift+PageDown` |

On macOS, `Cmd+Left`, `Cmd+Right`, `Cmd+Backspace`, `Option+Left`, and `Option+Right` forward standard shell line-editing actions (the shell must recognize them), while `Option` plus letter keys continue to compose dead-key characters.

`terminal.clear` drops selection, scrollback, and rows above the cursor while keeping the prompt row at the top; it is a no-op on the alternate screen. Copy is ignored when nothing is selected. Paste relies on the browser's native `paste` event (honoring bracketed paste mode when enabled by the app) so no default shortcut triggers a clipboard-read permission prompt.

## 3. Override bindings or disable defaults

Pass `bindings` to append custom shortcuts on top of `ghosttyKeymap[platform]` (later bindings override earlier ones). Pass `keymap: []` to start from an empty map. Pass `screenReaderMode: () => enabled` to suspend the five macOS text-navigation shortcuts while a screen reader is active, sharing the same predicate with `inputHooks.screenReaderMode` if your host configures it.

## 4. Integrate with a host dispatcher

Applications already running `@shaulavo/hotkeys` can pass `mode: 'hosted'` alongside their dispatcher, parent focus node, and platform so terminal shortcuts participate in global focus routing. Import `ghosttyKeymap` and `terminalShellKeysPack` from `ghostty-webgpu/hotkeys` to inspect or reuse the binding definitions. See [docs/hotkeys.md](https://github.com/ShaulLavo/ghostty-webgpu/blob/main/docs/hotkeys.md) for the focus adapter contract.

## Troubleshooting

### Copy fails silently or reports an error

`navigator.clipboard.writeText` requires a secure context and user gesture. Pass custom `clipboard: { readText, writeText }` and `onError` callbacks when embedding inside a desktop webview or custom clipboard policy.

### Attaching to a worker terminal throws a capability error

`attachTerminalHotkeys` requires synchronous `connectInput()` access to live native input modes (`alternateScreen` and `mouseReporting`), which is only available on the synchronous main-thread `Terminal`.
