The core `Terminal` encodes VT keys and Kitty keyboard protocol sequences without forcing an opinionated shortcut table on your app. When you want Ghostty's standard copy, clear, zoom, and scroll shortcuts, install the optional `@shaulavo/hotkeys` peer dependency and connect it with `ghostty-webgpu/hotkeys`.

## Attach shortcuts before opening

<Code code={sample} lang='ts' title='hotkeys.ts' />

Call `attachTerminalHotkeys(terminal, options)` before `terminal.open(host)`. The adapter claims original keyboard input through `terminal.connectInput()` once the terminal opens, and disposing either the returned handle or the terminal cleans up listeners and aborts pending clipboard work. Only one original-input owner can attach to a terminal at a time.

<Aside type='caution' title='Pitfall: main entry only'>
  `attachTerminalHotkeys` needs synchronous `connectInput()` access to live native input modes
  (`alternateScreen` and `mouseReporting`). Calling it on a `ghostty-webgpu/worker` terminal throws
  a `TerminalWorkerError` with `code: 'capability'`.
</Aside>

## Default Ghostty keymap

| Action                  | macOS                        | Linux and Windows                |
| ----------------------- | ---------------------------- | -------------------------------- |
| Copy selection          | `Cmd+C`                      | `Ctrl+Shift+C`                   |
| Select all              | `Cmd+A`                      | `Ctrl+Shift+A`                   |
| Clear above prompt      | `Cmd+K`                      | `Ctrl+Shift+K`                   |
| Increase font size      | `Cmd+=`                      | `Ctrl+=`                         |
| Decrease font size      | `Cmd+-`                      | `Ctrl+-`                         |
| Reset font size         | `Cmd+0`                      | `Ctrl+0`                         |
| Scroll to top or bottom | `Cmd+Home`, `Cmd+End`        | `Shift+Home`, `Shift+End`        |
| Scroll one page         | `Cmd+PageUp`, `Cmd+PageDown` | `Shift+PageUp`, `Shift+PageDown` |

On macOS, `Cmd+Left`, `Cmd+Right`, `Cmd+Backspace`, `Option+Left`, and `Option+Right` forward standard shell line-editing actions (the shell must recognize them), while `Option` plus letter keys continue to compose dead-key characters.

A few intentional behaviors keep shortcuts predictable:

- `terminal.clear` clears selection, scrollback, and rows above the cursor while keeping the active prompt row at the top; it is a no-op on the alternate screen.
- Copy does nothing when nothing is selected, letting `Ctrl+C` reach the shell as interrupt (`^C`).
- Paste uses the browser's native `paste` event (honoring bracketed paste mode when active) so no default shortcut triggers a clipboard-read permission prompt.

## Customize bindings or clipboards

- **Override or extend bindings:** Pass `bindings` to layer custom shortcuts on top of `ghosttyKeymap[platform]` (later bindings override earlier ones), or pass `keymap: []` to start from a blank slate.
- **Screen-reader compatibility:** Pass `screenReaderMode: () => enabled` to suspend the five macOS text-navigation shortcuts while a screen reader is active.
- **Custom clipboard environments:** `navigator.clipboard.writeText` requires a secure context and user gesture. In a desktop webview or custom host, pass `clipboard: { readText, writeText }` and `onError` callbacks.
