`ghostty-webgpu/worker` moves escape parsing, native screen state, Zig frame building, and WebGPU or WebGL2 rendering off the main thread onto an `OffscreenCanvas`. The page keeps a lightweight DOM host for focus, keyboard/pointer events, layout, and accessibility.

## When to use worker mode

Use the main entry when you have one or a few terminals and want the lowest total whole-browser CPU and synchronous `write()` / `readLines()` calls.

Switch to `ghostty-webgpu/worker` when:

- Your UI must stay responsive while multiple terminals stream heavy output.
- You render many simultaneous terminals (for example 8 to 16 panes) where main-thread parsing would exceed a 16.6 ms frame budget.
- You want a producer worker to stream PTY bytes directly into the terminal via `attachOutputPort()` without touching the page thread.

## 2. Host the worker and WASM assets

By default, the worker resolves `ghostty-vt.wasm`, `bridge.wasm`, and the worker bundle relative to the package module. For custom CDN paths or non-root base URLs, pass `assets: { wasm, bridge }` and `workerUrl` explicitly.

Check your Content Security Policy:

- `worker-src` must allow `workerUrl`.
- `script-src` must permit WebAssembly compilation (`'wasm-unsafe-eval'`).
- Cross-origin font and WASM URLs need matching CORS headers.

Worker mode communicates over `MessagePort` and transferable buffers. `SharedArrayBuffer` and cross-origin isolation (`COOP`/`COEP`) are not required.

## 3. Await async native operations

Because emulator state lives in the worker, operations that read or mutate native state return promises: `write`, `writeln`, `readLines`, `lineCount`, `geometry`, `setAppearance`, `setFont`, `setTheme`, `getSelection`, and `dispose`. Await a write before calling a read that depends on it. Pure DOM operations such as `focus()` and `blur()` stay synchronous.

The worker supports `backend: 'auto' | 'webgpu' | 'webgl'` (no Canvas 2D or DOM backends, and no `presentation: 'immediate'`). Host-side link providers (`registerLinkProvider`) and keyboard link discovery (`focusNextLink`) work over owned row snapshots. Synchronous original-input handlers (`connectInput`) and `ghostty-webgpu/hotkeys` remain main-entry capabilities.

How the pool schedules work:

- Starts one worker per terminal up to `workers` (default: `min(4, Math.floor(navigator.hardwareConcurrency / 2))`), then assigns additional terminals to the least-loaded worker.
- Shares a worker only among terminals with identical `workerUrl` and `fonts`.
- Terminals sharing a worker share its GPU device, glyph atlas, and font faces, and shut the worker down once its last terminal disposes.
- A single terminal error closes only that terminal; an unrecoverable worker crash fails every terminal leased on that worker.

## Troubleshooting

### Worker script or font returns 404

Relative URLs resolve against the current route, which breaks on nested paths. Pass bundler-resolved URLs (`new URL(..., import.meta.url)`) or absolute URLs for `workerUrl`, `assets`, and `fonts`.

### A method rejects with `TerminalWorkerError`

Inspect `error.code`, `error.why`, and `error.fix`. Capability errors (`code: 'capability'`) indicate a main-thread-only feature such as `connectInput`, `canvas2d-*`, or `presentation: 'immediate'`.
