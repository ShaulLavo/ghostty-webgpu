## When to choose worker mode

Stay on the main entry (`ghostty-webgpu`) when you mount one or a few terminals and want the lowest total whole-browser CPU plus synchronous `write()` and `readLines()`.

Switch to `ghostty-webgpu/worker` when:

- Your UI must stay smooth while multiple terminals stream heavy output simultaneously.
- You render many panes at once (for example 8 to 16 terminals) where main-thread parsing would blow past a 16.6 ms frame budget.
- You want a producer worker to stream PTY bytes directly into the terminal via `attachOutputPort(port)` without touching the page thread.

Workers do not inherit fonts loaded into the page's `document.fonts`. Pass every font face the worker needs through `fonts` as an absolute URL or raw `Uint8Array` bytes so the worker can register them in its own `FontFaceSet`, measure exact cell geometry, and rasterize glyphs.

<Aside type='caution' title='Pitfall: relative URLs on nested routes'>
  Relative paths for `workerUrl`, `assets`, or `fonts` resolve against the browser's current route
  and break on nested URLs like `/projects/123`. Always pass absolute URLs or bundler-resolved `new
  URL(..., import.meta.url)` values.
</Aside>

## Asset hosting and CSP

By default, the worker resolves `ghostty-vt.wasm`, `bridge.wasm`, and the worker bundle relative to the package module. Pass `assets: { wasm, bridge }` and `workerUrl` when serving from a custom CDN or non-root base path.

Check three Content Security Policy requirements:

- `worker-src` must allow `workerUrl`.
- `script-src` must permit WebAssembly compilation (`'wasm-unsafe-eval'`).
- Cross-origin font and WASM URLs need matching CORS headers.

Worker mode communicates over `MessagePort` and transferable buffers, so `SharedArrayBuffer` and cross-origin isolation (`COOP` / `COEP`) are **not** required.

## Async methods and capability boundaries

Because `libghostty-vt` lives inside the worker, every call that reads or mutates native state returns a promise: `write`, `writeln`, `readLines`, `lineCount`, `geometry`, `setAppearance`, `setFont`, `setTheme`, `getSelection`, and `dispose`. Await a write before calling a read that depends on it. Pure DOM methods like `focus()` and `blur()` remain synchronous.

Worker terminals support `backend: 'auto' | 'webgpu' | 'webgl'`, `registerLinkProvider`, and `focusNextLink`. Main-thread-only capabilities (`connectInput`, `ghostty-webgpu/hotkeys`, `canvas2d-*`, and `presentation: 'immediate'`) reject with a `TerminalWorkerError` whose `code`, `why`, and `fix` properties explain what failed.

      <li>
        Spawns one worker per terminal up to <code>workers</code> (default:{' '}

        <code>fonts</code>.
      </li>
      <li>
        Terminals on the same worker share its GPU device, glyph atlas, and font faces, and shut the
        worker down once the last terminal disposes.
      </li>
      <li>
        An error in one terminal closes only that terminal; an unrecoverable worker crash fails
        every terminal leased on that worker.
      </li>
    </ul>
