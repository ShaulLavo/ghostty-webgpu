`ghostty-webgpu` represents colors as explicit `{ r, g, b }` integer objects and passes them straight into `libghostty-vt` and the renderers.

## 1. Apply a theme

<Code code={sample} lang='ts' title='theme.ts' />

`TerminalTheme` requires named colors (`background`, `foreground`, `cursor`, `selectionBackground`, `selectionForeground`, optional `cursorText`), `minimumContrast`, and a `palette` array with exactly 256 RGB entries. Spread `terminal.appearance.theme` when updating only a subset of named colors so the 256-color palette stays intact.

`minimumContrast` enforces a minimum WCAG contrast ratio between a cell's resolved foreground and background colors (default `1` disables adjustment).

## 2. Batch appearance updates

Use `terminal.setAppearance({ theme, font, cursor, backgroundOpacity, colorScheme })` when multiple visual settings change together so the session commits one atomic revision and triggers a single repaint. Use `setTheme`, `setFont`, `setCursor`, or `setColorScheme` for isolated updates. On the worker entry, all appearance setters return promises.

## 3. Control background opacity

The root `.ghostty-webgpu` container paints the default theme background across the full element, including padding and remainder pixels outside the cell grid, while renderers leave default-background cells transparent. `backgroundOpacity` controls the alpha of that root fill (from `0` to `1`, default `1`, matching Ghostty's `background-opacity`).

Pass `setAppearance({ backgroundOpacity: 0.85 })` to let a page backdrop show through, or `0` to paint your own surface behind the terminal. Cells with an explicit SGR background color remain opaque.

## 4. Resolve a host Ghostty config

`ghostty-webgpu/config-resolver` runs in Node or Bun and invokes a native helper binary on supported macOS (`darwin-arm64`, `darwin-x64`) and Linux (`linux-arm64`, `linux-x64`) hosts to parse a user's Ghostty configuration file into a structured appearance object (including `surface.backgroundOpacity` and light/dark profiles).

Keep `ghostty-webgpu/config-resolver` strictly on the server and forward only the resolved appearance JSON to the browser client. See the [config resolver guide](https://github.com/ShaulLavo/ghostty-webgpu/blob/main/docs/config-resolver.md) and [Config resolver API](https://ghostty.shaulavo.dev/docs/reference/config-api/) for manifest checks and native helper setup.

## Troubleshooting

### `setTheme` throws on the palette

`palette` must have length `256` with valid 0..255 integer RGB channels. Clone `terminal.appearance.theme.palette` if you only want to override specific ANSI indices.

### The config resolver reports a missing helper

Source checkouts hold only the bootstrap manifest until the native helper binaries are assembled for your platform. The browser terminal works independently without the host config resolver.
