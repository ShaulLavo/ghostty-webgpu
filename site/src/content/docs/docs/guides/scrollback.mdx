`ghostty-webgpu` exposes Ghostty's native scrollback directly through `lineCount()` and `readLines()`, leaving scroll position and active selection untouched.

## 1. Read retained lines

<Code code={sample} lang='ts' title='history.ts' />

- `lineCount()` returns total retained history rows plus visible rows on the active screen (including blank visible rows).
- `readLines(start, end, options)` reads the clamped, oldest-first half-open interval `[start, end)`.
- Each returned `TerminalLine` contains `{ text, wrapped }`. `wrapped: true` indicates the row soft-wrapped into the next physical row (so you can rejoin wrapped lines when exporting logs). `trimRight` defaults to `true`.

A single `readLines()` call returns at most `TERMINAL_READ_LINES_MAX_ROWS` (1,024 rows). For larger exports, paginate by advancing `start` by the count returned. Because incoming writes, page eviction, or resize reflow can shift row indices between calls, pause your producer when taking a consistent multi-page dump.

## 2. Configure retention budgets

<Code code={retention} lang='ts' title='retention.ts' />

Ghostty allocates terminal history in pages whose row capacity depends on terminal width, styles, and grapheme data. Two independent limits control pruning:

- `appearance.scrollbackLimit`: caps physical history rows above the active screen. Because Ghostty prunes whole pages and keeps at least one standard page intact, small values (including `0`) can still retain rows that share a page with the active area.
- `appearance.scrollbackByteLimit`: caps logical page memory across both scrollback and the active screen. Any positive value is raised to Ghostty's minimum allocation (active area plus one extra page). Setting `scrollbackByteLimit: 0` immediately discards retained history and disables future scrollback.

When both budgets are set, whichever limit is reached first triggers page eviction.

## 3. Live state vs. displayed viewport

- `readLines()` reads live `libghostty-vt` state immediately after `write()`, even before the next animation frame paints. While the alternate screen (for example `vim` or `htop`) is active, `readLines()` reads the alternate screen; exiting returns to primary history.
- `visibleLines()` reads the last frame submitted to the renderer, matching what is currently painted on screen.

## Troubleshooting

### `readLines()` returns fewer rows than requested

Check the 1,024-row per-call cap, `lineCount()`, and whether the terminal is currently on the alternate screen. Out-of-bounds intervals clamp silently to `[0, lineCount())`.

### Restoring a saved viewport after reload does not restore shell history

`captureViewport()` encodes a compact visual checkpoint (`paintTerminalViewport`) for instant first paint, not live emulator history. Restore emulator state by replaying retained PTY bytes or reconnecting to a persistent server session. See [docs/saved-viewport.md](https://github.com/ShaulLavo/ghostty-webgpu/blob/main/docs/saved-viewport.md).
