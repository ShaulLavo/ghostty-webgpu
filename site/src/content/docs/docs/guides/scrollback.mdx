## Read retained lines

<Code code={sample} lang='ts' title='history.ts' />

- `lineCount()` returns total retained history rows plus visible rows on the active screen (including blank visible rows).
- `readLines(start, end, options)` returns the clamped, oldest-first half-open range `[start, end)`. Out-of-bounds indices clamp silently to `[0, lineCount())`.
- Each `TerminalLine` contains `{ text, wrapped }`. When `wrapped` is `true`, the row soft-wrapped into the next physical row, so you can rejoin wrapped lines when exporting logs. `trimRight` defaults to `true`.

A single `readLines()` call returns at most `TERMINAL_READ_LINES_MAX_ROWS` (**1,024 rows**). For larger exports, paginate by advancing `start` by the count returned.

<Aside type='caution' title='Pitfall: shifting indices during multi-page exports'>
  Incoming writes, page eviction, or resize reflow can shift row indices between paginated calls,
  and entering the alternate screen (for example `vim` or `htop`) switches `readLines()` to the
  alternate screen's rows. Pause your producer if you need a single consistent snapshot across more
  than 1,024 rows.
</Aside>

## Configure retention budgets

<Code code={retention} lang='ts' title='retention.ts' />

Ghostty allocates terminal history in fixed-size memory pages whose row capacity depends on terminal width, styles, and grapheme data. Two independent limits control eviction:

- **`appearance.scrollbackLimit`:** caps physical history rows above the active screen. Because Ghostty prunes whole pages and keeps at least one standard page intact, small values (including `0`) can still retain rows that share a page with the active viewport.
- **`appearance.scrollbackByteLimit`:** caps logical page memory across both scrollback and the active screen. Any positive value is raised to Ghostty's minimum allocation (active screen plus one extra page). Setting `scrollbackByteLimit: 0` immediately discards retained history and disables future scrollback.

When both budgets are set, whichever limit is hit first triggers page eviction.

## Choosing the right read API

| API                 | Reads from                                   | Best for                                                            |
| ------------------- | -------------------------------------------- | ------------------------------------------------------------------- |
| `readLines()`       | Live `libghostty-vt` active screen + history | Exporting logs, inspecting output right after `write()`             |
| `visibleLines()`    | Last frame submitted to the renderer         | UI overlays and tests checking what is actually painted             |
| `captureViewport()` | Compact serialized viewport snapshot         | Instant visual first paint before a PTY reconnects (not live state) |

<details class='deep-dive'>
  <summary>Why captureViewport() is not a history backup</summary>
  <div class='deep-dive__body'>
    <p>
      <code>captureViewport()</code> serializes only the currently visible cells into a compact
      payload that <code>paintTerminalViewport</code> can draw immediately on reload. It does not
      store scrollback, modes, or live PTY state. To restore an interactive session after reload,
      replay retained PTY bytes or reattach to a persistent server session (see{' '}
      <a href='https://github.com/ShaulLavo/ghostty-webgpu/blob/main/docs/saved-viewport.md'>
        docs/saved-viewport.md
      </a>
      ).
    </p>
  </div>
</details>
