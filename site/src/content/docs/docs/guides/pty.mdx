This guide wires a browser `Terminal` to a WebSocket PTY endpoint without string round-trips. You need a sized host element and a server that exchanges raw terminal bytes as binary frames and accepts JSON resize messages (see [A real shell in the browser](https://ghostty.shaulavo.dev/docs/start/real-shell/) for a ready-to-run Bun server).

## 2. Keep terminal I/O in bytes

- Set `socket.binaryType = 'arraybuffer'`.
- Feed incoming binary frames directly into `terminal.write(new Uint8Array(data))`. `libghostty-vt` decodes UTF-8 incrementally across writes, including multi-byte sequences split across WebSocket frames.
- Forward `terminal.onData(({ bytes }) => ...)` directly as binary frames. Never round-trip raw PTY bytes through `TextDecoder` or UTF-16 strings.

Because `await terminal.open(host)` fits the grid synchronously before resolving, `terminal.geometry()` already reflects the host element's exact columns and rows when the socket's `open` listener calls `sendSize()`. Subsequent viewport or font changes fire `terminal.onResize` and push updated `{ type: 'resize', columns, rows }` messages.

## 3. Flow control and batching

For heavy streaming output:

- **Producer pacing:** Watch `socket.bufferedAmount` on the server and pause PTY reads once queued bytes pass your high-water mark, resuming after drain.
- **Client batching:** On bursty streams, `terminal.writeBatched(bytes)` coalesces writes across frames under a configurable byte budget (`writeQueue` option) instead of forcing synchronous parsing on every tiny chunk.
- **Parse vs. paint:** `terminal.write()` updates native emulator state immediately, while painting happens on the scheduler's frame boundary. Listen to `terminal.onFrame` if you need to know when rows were submitted to the renderer, and keep network flow-control acknowledgements separate from render notifications.
- **Worker output ports:** In `ghostty-webgpu/worker`, you can transfer a producer's `MessagePort` directly to the terminal worker with `attachOutputPort(port)` and coordinate draining with `fenceOutput(sequence)` so bulk PTY traffic bypasses the main thread altogether.

## Troubleshooting

### Reconnecting shows stale screen text or an empty shell

Opening a fresh WebSocket requires an explicit server session policy: either reattach to an existing PTY and replay its buffered output, or spawn a new shell and call `terminal.reset()`. `captureViewport()` saves a visual snapshot for instant paint, not live emulator state.

### Incoming frames arrive as strings instead of `ArrayBuffer`

Ensure the server sends binary WebSocket frames for PTY output. The client ignores text frames so text remains available for JSON control messages.
