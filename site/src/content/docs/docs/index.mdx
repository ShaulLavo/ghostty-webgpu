`ghostty-webgpu` runs Ghostty's unpatched `libghostty-vt` terminal core in WebAssembly and pairs it with a browser host and four renderers. Use it to embed interactive shells, build logs, or local command prompts inside a web app.

Start with [First terminal](https://ghostty.shaulavo.dev/docs/start/quick-start/) for a working local prompt, or [A real shell](https://ghostty.shaulavo.dev/docs/start/real-shell/) to wire Bash over WebSocket.

## Architecture at a glance

One native `libghostty-vt` instance owns escape parsing, active screen state, modes, scrollback, selection coordinates, and Unicode cell widths. Four renderers read from that single state:

- **WebGPU and WebGL2** feed persistent cell and glyph buffers built in Zig (`bridge.wasm`) and upload only dirty byte ranges.
- **Canvas 2D** paints the first frame immediately during frame presentation while WebGPU or WebGL2 warms up, then swaps the painted GPU canvas in place without flashing. It also serves as the fallback when neither GPU API is available.
- **DOM** renders plain styled rows when Canvas is unavailable or explicitly requested via `rendererFactory`.

`await terminal.open(host)` measures the host container synchronously before constructing the renderer, so `terminal.appearance.grid` and `terminal.geometry()` already hold the fitted column and row counts when `open()` resolves.

## Entry points

| Entry point                      | Environment     | Purpose                                                                                                                                   |
| -------------------------------- | --------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `ghostty-webgpu`                 | Browser         | Main-thread `Terminal` host with automatic fitting, selection, links, scrollback, and Canvas-first GPU startup.                           |
| `ghostty-webgpu/worker`          | Browser         | Runs `libghostty-vt`, Zig frame building, and WebGPU/WebGL2 rendering in a dedicated worker or `TerminalWorkerPool` on `OffscreenCanvas`. |
| `ghostty-webgpu/core`            | Browser or Node | Headless `GhosttyRuntime`, `GhosttyTerminal`, and `TerminalSession` with no DOM or renderer imports.                                      |
| `ghostty-webgpu/hotkeys`         | Browser         | Optional Ghostty keymap adapter (`attachTerminalHotkeys`) backed by `@shaulavo/hotkeys`.                                                  |
| `ghostty-webgpu/config-resolver` | Node or Bun     | Resolves host Ghostty config files into terminal appearance objects.                                                                      |

## Current scope and limits

Shipped features include DEC mode 2026 synchronized output, mode 2027 grapheme clustering, opt-in GSUB ligatures (`ligatures`), lazy Unicode 13.0 BiDi (`bidi`), OSC 8 hyperlinks, URL detection, and an opt-in screen-reader text mirror (`accessibility: {}`).

Retained-buffer search, Sixel and Kitty image protocols, and a formal screen-reader audit remain open work. See [status and limits](https://github.com/ShaulLavo/ghostty-webgpu/blob/main/docs/status.md) and the [changelog](https://github.com/ShaulLavo/ghostty-webgpu/blob/main/CHANGELOG.md) for release-specific notes.
