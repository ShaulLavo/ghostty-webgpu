---
title: Damage tracking
description: How libghostty-vt dirty state, Zig instance diffing, row reuse, and synchronized output minimize per-frame work.
---

Redrawing every cell on every animation frame wastes CPU and GPU bandwidth whenever only a prompt line or cursor moved. `ghostty-webgpu` propagates dirty state from `libghostty-vt` all the way to GPU buffer uploads and Canvas/DOM row updates.

```text
write() / resize / setAppearance()
               |
               v
   libghostty-vt dirty flags (false / partial / full)
               |
               v
   bridge.wasm rebuilds only dirty rows into persistent buffers
               |
               v
   upload changed byte ranges (WebGPU/WebGL2) or repaint rows (Canvas/DOM)
               |
               v
      emit submittedFrame / onFrame / onText
```

## What each backend skips

- **Idle frames:** when `renderState.update()` reports no damage and neither cursor blink nor text blink changed phase, the renderer skips drawing and submits zero GPU commands.
- **Repeated identical screens:** if an application rewrites the same characters and styles (for example a TUI redrawing unchanged panels), byte-level comparison against the persistent Zig instance records skips unnecessary uploads. In the November 2026 benchmarks, `repeated-ascii` runs at `0.20x` to `0.36x` the CPU of the best competitor.
- **Full-viewport scrolling:** both WebGPU and WebGL2 retain physical row slots across full-viewport scrolls and shift them visually via shader row offsets, rebuilding only newly exposed rows (WebGPU disables slot reuse only when glyph instances split across multiple draw batches). Canvas 2D copies unchanged rows in place via `drawImage` self-copy when device row height is integral.
- **Single-line edits:** Canvas 2D tracks per-row plain-text damage to repaint only the changed horizontal span (plus glyph overhang); GPU backends upload only the modified byte slices of the persistent instance buffer.
- **Synchronized output (DEC mode 2026):** while an application holds mode 2026 active (`CSI ? 2026 h`), the renderer defers painting until release (`CSI ? 2026 l`) or safety timeout, avoiding half-drawn frames and suppressing Canvas-to-GPU startup swaps mid-frame.

A container resize, font metric change, theme/palette change, or GPU device restoration triggers a full rebuild so every cell reflects the new geometry or colors.

## Coherent snapshots for observers

Observers that overlay UI on the terminal (such as link hit-testing, accessibility mirrors, or IME caret placement) need text that matches the pixels currently on screen rather than bytes that were just parsed and not yet drawn.

- `terminal.submittedFrame` exposes the immutable metadata (`frame`, `nativeRevision`, `grid`, `font`, `padding`, `cursor`, `selection`, `scrollbar`) for the last presented frame.
- `terminal.onFrame(({ rows }) => ...)` fires with the row indices updated in each submitted frame.
- `terminal.onText(({ frame, rows, rowPatches }) => ...)` delivers text snapshots synchronized with presentation.
- `terminal.refresh(startRow, endRow)` marks a row range dirty on demand; `terminal.clearTextureAtlas()` flushes cached glyph bitmaps so newly loaded fonts rasterize fresh.

See [TerminalSubmittedFrame](https://ghostty.shaulavo.dev/docs/reference/api/interfaces/terminalsubmittedframe/) in the API reference or review measured costs in [Benchmarks](https://ghostty.shaulavo.dev/docs/concepts/benchmarks/).
