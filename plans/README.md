# ghostty-webgpu Execution Plans

Generated by the `improve` planning workflow on 2026-08-24. Plans 001–005 align the
`ghostty-webgpu` text renderer with the proven behavioral architecture of xterm.js's WebGL
renderer while keeping this project WebGPU-native. Plans 006–015 add framework-agnostic TanStack
hotkey arbitration and a separately testable, versioned xterm compatibility program.

The renderer reference was inspected at xterm.js commit
[`8938fe37852995761d28c20edb74ee3986e8c438`](https://github.com/xtermjs/xterm.js/tree/8938fe37852995761d28c20edb74ee3986e8c438/addons/addon-webgl/src).
The compatibility program will pin current xterm.js source commit
[`08ad9a4de9252f387cc5fbf68aa3d98e0ba8a0b7`](https://github.com/xtermjs/xterm.js/tree/08ad9a4de9252f387cc5fbf68aa3d98e0ba8a0b7)
under `references/xterm.js` and certify released core/headless version 6.0.0 at tag commit
[`f447274f430fd22513f6adbf9862d19524471c04`](https://github.com/xtermjs/xterm.js/tree/f447274f430fd22513f6adbf9862d19524471c04).
Executors use immutable commits/package versions, never moving `master`.

Execute in the order below. Each executor must read its plan fully, honor its STOP conditions, run
every verification gate, and update its status row when finished.

## xterm alignment map

| Pinned xterm concept                                             | `ghostty-webgpu` target                                                           | Plan    |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------------- | ------- |
| Integer device character/cell dimensions; CSS derived afterward  | One immutable fitted-font value with separate character and cell geometry         | 005     |
| Padded scratch rasterization and alpha-bounded glyph size/offset | Bearing-aware cropped Canvas bitmaps and actual-size WebGPU quads                 | 003     |
| Style-sensitive character-atlas identity                         | Text/span/weight/italic cache identity; faint remains a shader multiplier         | 003     |
| `GlyphRenderer` cell position + offset + size + texture page     | Glyph instances carry signed placement, actual size, layer, and UVs               | 003–004 |
| Multiple atlas pages with page/version invalidation              | Fixed WebGPU texture-array layers with generation-safe row invalidation           | 004     |
| Device/CSS dimension reflow on font, DPR, and option changes     | Canonical fit result applied once across DOM, Ghostty grid, pointer, and renderer | 005     |

The alignment is behavioral, not a source port. xterm's current WebGL atlas bakes resolved colors and
several decorations into RGBA glyph textures. This package deliberately keeps grayscale coverage
recolorable and renders fixed-cell effects in its first draw, because Ghostty supplies structured
cell styles and the existing renderer promises exactly two draws. Plan 002 establishes that seam
before glyph rectangles become variable.

## Compatibility architecture

```text
KeyboardEvent
  -> xterm custom-key first refusal
  -> vanilla @tanstack/hotkeys host-command arbitration
  -> Ghostty physical-key/IME/paste transport
  -> native Ghostty key encoder / PTY bytes

@xterm/* consumer imports
  -> package-manager aliases to @ghostty-webgpu/*
  -> xterm-compatible browser/headless/addon facades
  -> ghostty-webgpu native session + renderer
```

TanStack hotkeys is the shortcut layer, not a terminal protocol encoder. Physical `code`, modifier
sides/locks, AltGraph, composition, and Kitty press/repeat/release stay on the native Ghostty path.
The compatibility facade remains on `ghostty-webgpu/xterm`, so native consumers do not inherit
xterm naming or lifecycle compromises.

“Full parity” is versioned and measurable. It requires a complete public API/option/event/addon/
headless/package/browser ledger, behavioral evidence for every compatible row, a zero-gap final
gate, and recorded physical input/accessibility checks. Type-name similarity or a cloned reference
alone is not parity.

## Dependency notes

- Plan 001 adds characterization scenes and atlas-upload metrics before any structural change. The
  later plans depend on its baseline so performance and pixel behavior cannot silently regress.
- Plan 002 moves cursor and decoration coverage onto fixed cell geometry. Cropped glyph quads in
  Plan 003 are unsafe until this separation exists.
- Plan 003 changes glyph bitmap and instance contracts. Plan 004 must consume the settled glyph
  metadata rather than redesigning atlas storage and glyph geometry simultaneously.
- Plan 004 establishes stable texture-array bindings and dirty-region uploads. Plan 005 then
  measures final font/DPR behavior and performance instead of qualifying a temporary atlas path.
- Do not resume the physical Phase 3 operator gate until all five plans are DONE and the corrected
  renderer is loaded in the headed demo. The existing input, IME, clipboard, and VoiceOver checklist
  remains authoritative.
- Plan 006 isolates vanilla hotkey policy and manual input ownership before the xterm facade depends
  on custom key-handler semantics.
- Plan 007 pins reference source/released packages and creates the parity ledger. Plan 008 starts
  only after Plans 006 and 007 are DONE.
- Plan 008 solves synchronous xterm construction/open observables over asynchronous WASM creation.
  Its qualified completion transfers every unresolved row to Plans 009, 010, 014, or 015 without
  promotion. The accepted visual-hard-clear and native-write-lifecycle divergences remain partial
  under Plan 015, so Plan 008 DONE is not a full-parity claim. Plan 009 then adds native-backed
  buffer/parser/Unicode/extensibility surfaces; no shadow parser or visible-row proxy is allowed.
- Plan 010 completes browser interaction and accessibility. Plans 011–013 qualify every official
  addon group against those public surfaces.
- Plan 014 adds headless behavior and package-manager-alias distribution. Plan 015 is the only plan
  allowed to make the versioned parity/drop-in claim, and its zero-gap criterion remains
  unsatisfied while either accepted Plan 008 divergence stays partial.

## Program invariants

Every plan must preserve these project-specific constraints:

- Ghostty's render state remains the authority for cells, continuation width, styles, colors,
  selection, cursor state, and damage.
- The text fast path remains two instanced draws: one fixed-cell pass and one glyph pass.
- Default cells remain transparent; explicit backgrounds remain opaque; output remains
  premultiplied alpha.
- Dirty rows are acknowledged only after successful GPU submission.
- Atlas recycling remains generation-safe and invalidates every referencing row.
- No standing render loop or unbounded maintenance timer is introduced.
- CSS grid, native terminal geometry, pointer projection, and device backing pixels remain derived
  from one canonical device-pixel grid.
- Ghostty remains the VT/buffer authority. Compatibility code never maintains a second parser or
  scrollback model.
- Public xterm behavior is implemented from pinned types/tests/reference behavior; production code
  does not import xterm private runtime services.
- The xterm reference submodule and released test packages never ship in production artifacts.
- External side effects remain explicit: no unsafe URL navigation, clipboard permission escalation,
  registry publication, push, tag, or release without operator authority.
- All new or refactored functions obey `AGENTS.md`: nesting depth at most three, early returns,
  exact imports, short comments, and no nested ternaries.

## Findings considered and rejected

- **Copy xterm.js source wholesale**: rejected. Its behavior is the reference, but its WebGL texture
  units, color-baked atlas, services, and renderer model do not match this WebGPU package. Adapt the
  design and write project-native code.
- **Bake terminal colors into glyph atlas entries**: rejected. The existing grayscale-coverage atlas
  allows shader recoloring, selection, inverse video, minimum contrast, and theme changes without
  duplicating glyph bitmaps.
- **Variable-size atlas page merging**: rejected for this refactor. WebGPU texture arrays require
  equal layer dimensions; fixed-size layers plus generation-safe recycling are the native mapping.
- **Idle-callback ASCII warmup**: deferred. It conflicts with the project's no-standing-work
  acceptance contract unless measurements prove a bounded maintenance task is worth owning.
- **Run every terminal key through hotkey matching**: rejected. Shortcut matchers use layout-level
  `event.key`; terminal protocols require physical code, modifier sides, IME, and key lifecycle.
- **Own TanStack's global HotkeyManager singleton**: rejected. One terminal must not destroy or
  mutate application/global registrations. Plan 006 uses vanilla parse/normalize/match primitives
  inside the terminal's existing event owner.
- **Fake xterm buffer/parser APIs from visible rendered rows**: rejected. It loses scrollback,
  inactive buffers, parser fallback ordering, and Unicode width authority. Plan 009 requires native
  libghostty hooks or stops for an upstream decision.
- **Publish under the upstream `@xterm` npm scope**: rejected. Plan 014 uses operator-owned package
  names plus dependency aliases, preserving application imports without impersonating upstream.
- **Treat cloning xterm as implementation**: rejected. The pinned submodule is a source/provenance
  reference and inventory input. Each feature still needs project-native code and differential
  evidence.
- **Import xterm's full custom-glyph definitions without review**: rejected. Plan 013 requires an
  explicit licensing/provenance review before adapting analytic glyph definitions.
