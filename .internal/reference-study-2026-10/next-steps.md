# Next steps after the reference study

Status: Approved. Date: 2026-10-27. Source: [the study](README.md), merged at `d2ed8989a`.

This is the execution plan for everything the study found. Each item has an ID, a gate and a done condition. An item is done when its PR is merged, or when its experiment has a keep or reject decision written in `.internal/`. Experiment IDs (E1–E8) and ranked items (1–18) refer to the study's [ranked plan](README.md#ranked-improvement-plan) and [experiment briefs](README.md#experiment-briefs). Where an item says "per E*n*", the study's full brief is part of its contract. [Coverage](#coverage) maps every study recommendation and lane finding to an item here or to a recorded deferral.

## Constraints

These come from the study and apply to every item. Changing one needs new evidence and an ADR.

- Keep the unpatched pinned Ghostty core and the separate bridge (ADR 001). No patched Ghostty API.
- Keep the instanced WebGPU renderer (ADR 002) and the paged atlas allocator.
- Keep Canvas per-glyph painting in the Canvas backend; word-run replay already failed on contextual alternates.
- No full-viewport frame rebuilding, full-buffer uploads, or fixed clear-and-rebuild atlases.
- Browser rasterization stays the default. Any WASM font stack is opt-in.

## Ground rules

- **Baseline first, then change.** Every performance item gets a same-session, counterbalanced before/after pair on hardware with the existing `bench:renderer` / `bench:compare` tooling and the study's workloads (`/work/reports/ghostty-webgpu-reference-study-2026-10-27/bench/workloads/`).
- **Equal output is a prerequisite.** Every performance PR shows equal text and pixels (including wide, combining, overhanging and color glyphs) and equal parsed, submitted and presented update counts. A speedup that skips work is a failure.
- **Endpoints are separate facts.** Write acknowledgement, frame submission, GPU queue completion and presentation are different measurements. Presentation means a Chrome `AnimationFrame::Presentation` trace event joined to our frame by command or frame identity. Screenshots prove content, not timing.
- **Two hardware hosts, used in turns.**
  - PC: RTX 3060 Ti, Linux. WebGL2 is the default backend there.
  - M1 Mac: WebGPU is the default backend there.
  - Each result names its host, browser, adapter and source SHAs.
- **Check VRAM before every headed window on the PC.** During the study, Hyprland's GPU memory grew to 6.96 GiB with many headed benchmark windows, and WebGPU device creation failed. Check `nvidia-smi` first and stop if free VRAM is under 2 GiB. Keep one headed benchmark browser open at a time.
- **One PR per item**, each with an independent reviewer that isn't its author. Changes touching the same files land in the order under [Dependencies](#dependencies-and-order).

## Dependencies and order

- **Start now:** M1–M8, F3, F5–F11, X3, X4 (WebGL2 prototype), B1–B4. None waits on another.
- **F2** needs M1 from both hosts.
- **F3** lands before X1, which shares the atlas F3 reshapes.
- **F6** lands before F4; both touch the bridge row plan. X6 waits for both and for M3.
- **X2** needs M1. **X5** and **C2's** rasterization choice wait for M3. **X7** waits for B1, which changes render-state ownership. **X8** needs M2's GPU timing.
- **C2 and C3** start their correctness sets during Phase 2 and their prototypes after it.

## Decisions

- **Ligatures (C2) and BiDi (C3) run after Phase 2** (owner left it to the coordinator, 2026-10-27). Neither is a gap against the ghostty-web baseline, and Phases 1 and 2 address measured costs.
- **C2 starts with browser-rasterized joined runs.** A WASM shaper is reconsidered only if M3 shows wraithterm's in-WASM font path winning end to end. This replaces the study's open framing of item 13.
- **Global instructions corrected** (owner, 2026-10-27): `~/.agents/AGENTS.md` now describes ghostty-webgpu, singapore and hotkeys as standalone repos.
