## 2. State and memory ownership

Provenance names official unpatched freestanding ReleaseSmall core,821390 bytes, and separate bridge,20910 bytes, built with --import-memory. Runtime compiles both in parallel, instantiates core first, reads ghostty_type_json ABI layouts, then instantiates bridge with env containing core exports plus JS effect handlers. Default loading is fetch/read -> arrayBuffer -> compile, not streaming instantiation or global module caching. Callers may supply compiled WebAssembly.Modules. Core and bridge share **one ordinary wasm memory in the same realm**. Bridge allocation imports ghostty_wasm_alloc/free; there is no whole-frame core-to-bridge memory copy. JS reserves the bridge's separate64KiB stack inside core memory and sets its stack pointer. Imported C calls are actual core wasm exports, not JS forwarding functions. They cross wasm-instance/import boundaries but are not one JS call per cell. No SharedArrayBuffer/Atomics, parser/render mutex or concurrent core access exists.
