# Terminal selection copy fix

The playground uses `Terminal.create` with `canvas2d-fill-text`. Before the fix, a
Chromium regression run against the packaged entries failed all three main-thread
copy callback cases (Mac, Linux, Windows), plus Linux and Windows worker cases.
Only worker Mac passed. Each failure observed an empty copy callback result after
selecting native terminal text and dispatching the platform copy shortcut.

Reproduce the regression coverage:

```sh
bun run build
bun run test:browser src/dom/tests/selection-packaged.browser.test.ts src/dom/tests/terminal-input.browser.test.ts src/dom/tests/terminal-ui.browser.test.ts
```

The packaged main-thread fixture uses `canvas2d-fill-text`, matching the playground.
Chromium gets clipboard permissions in its test context. Real clipboard tests send
trusted Command+C events and read the clipboard back; callback tests cover all
three platform conventions, both execution modes, and plain Ctrl+C with and without
selection. The existing worker activation test checks that delayed native readback
still starts a browser clipboard write during the trusted key event.
